# コメントを拡充した学習用コピー

正本 [procedural-migration](../procedural-migration/README.md) の主要6本に、日本語の説明コメントを追加した学習用フォルダです。コード内のコメントは処理の目的、関数の仕様、間違えやすい条件に絞り、PowerShellの基本構文は下の早見表にまとめています。

**正本のコードは変更していません。このフォルダも同じ操作を行うコードです。** Azureの作成・変更・削除を行うため、実際の作業は正本へ統一してください。`targets.csv`・`records/`・結果CSVはスクリプトのあるフォルダを基準に扱うので、作業途中に正本と学習版を切り替えないでください。

本文ではSubをサブスクリプション、RGをリソースグループと呼びます。DCRはデータ収集ルール、LAWはLog Analyticsワークスペースの略です。

## 最初に読む場所

|順番|ファイル|注目すること|
|---|---|---|
|1|[step1_copy.ps1](step1_copy.ps1)|旧設定の調査→変更前記録→適用除外→保存先→新設定の順を追う|
|2|[common.ps1](common.ps1)|最初は設定値とCSV読込みを確認し、関数は呼ばれたときに参照する|
|3|[step2_verify.ps1](step2_verify.ps1)|記録と現在のAzureを照合し、削除へ進める状態か確認する|
|4|[step3_delete.ps1](step3_delete.ps1)|全件確認が成功してから、指定した旧設定だけを削除する|
|5|[rollback.ps1](rollback.ps1)|旧設定を全件戻した後、新しい送信設定を外す順番を理解する|
|補足|[precheck.ps1](precheck.ps1)|設定を変更せず、事前確認だけを行う。step1の必須前提ではない|

commonの全関数を最初に覚える必要はありません。step1に出てくる関数名を見て、その関数の区切りコメントへ移動してください。コメントには引数・戻り値・止まる条件も記載しています。

## PowerShellの書き方

|書き方|意味・このコードでの使い方|
|---|---|
|`$target`|値を入れる変数。ここではCSVの1行分を表す|

|`@(...)`|0件・1件でも一覧の形で扱うための配列|
|`[ordered]@{...}`|項目を指定した順番で保持する辞書|
|`[pscustomobject]@{...}`|CSVの1行など、項目を持つデータを作る|
|`$true` / `$false`|はい／いいえを表す値|
|`$null`|値がないことを表す。空文字やfalseとは別|
|`$null = 処理`|その処理から返る値を使わずに捨てる|
|`-eq` / `-ne`|等しい／等しくないか比較する|
|`-in` / `-notin`|指定した一覧に含まれる／含まれないか調べる|
|`-and` / `-or` / `-not`|条件を「両方」「どちらか」「反対」で組み合わせる|
|`-match` / `-replace`|文字列のパターンを調べる／置き換える|
|`??`|左側がnullの場合だけ、右側の値を使う|
|`foreach ($item in $items)`|一覧から1件ずつ取り出して処理する|
|`if (...) { ... }`|条件に合うときに処理を行う|
|`try { ... } catch { ... }`|処理と、失敗した場合の対応を分ける|
|`throw`|エラーとして、その処理の続行を止める|
|`continue` / `break`|次の繰り返しへ進む／そのループを抜ける|
|`return`|関数や処理ブロックから値を返して、その呼出しを終える|
|`一覧 \| Where-Object { ... }`|一覧の中から、条件に合うものだけを取り出す|
|`$_`|パイプで処理中の1件。catchの中では捕まえたエラー|
|`$()`|ダブルクォートの文字列内などで、式を計算して値を埋め込む|
|`. ファイル.ps1`|変数や関数を、呼出し元でも使えるように読み込む（ドットソース）|

関数の呼出しで使う `-Target` などは引数名です。たとえば `Get-MigrationPlan -Target $target` は、「Targetという引数に、いまのCSV行を渡す」という意味です。`-Optional`のようなswitchは、その名前を付けることで有効になります。

## 変数と記録のつながり

|名前|中身|
|---|---|
|`$targets`|CSVから読んだ、今回処理するSubの一覧|
|`$target`|そのうちの1行。新しい保存先名と送信先の選択を持つ|
|`$plan`|今回の調査で得た旧設定と、これから準備する内容|
|`$record`|変更前記録。再実行・確認・削除・切り戻しで参照する|
|`$resource` / `$setting`|いま処理している1件の保存先や設定|
|`$current`|Azureへ問い合わせて取得した現在値|
|`$expected`|設定または照合したい期待値|
|`$before` / `Before`|変更前の値。元からなければnull|
|`$failures` / `$results`|失敗一覧／確認結果の一覧。最後にCSVへ出す|

これらの変数はファイルや関数の中でそれぞれ使われます。同じ名前でも、別の呼出しや並列workerの変数まで常に共有されるわけではありません。

記録には、`Destinations`（保存先）、`NewSettings`（新設定・適用除外）、`OldSettings`（旧設定）の3一覧があります。1件のデータは `Id`（操作先）、`Kind`（用途の分類）、`Body`（設定値）を持ち、必要なものだけ `Before`（変更前）も持ちます。`Kind`はスクリプト内の分類で、Azureが返すリソースの`type`やStorageの`kind`とは用途が違います。

変更前記録はログデータのコピーではありません。旧設定を復元するための値と、今回そろえる設定値を保存しています。最初の`Before`を再実行でも残す理由は、途中で作った新設定を「元からあった設定」と取り違えないためです。

## 読むときに押さえる処理の境目

- precheckは確認だけを行い、変更前記録を作らない。step1は必ずその時点のAzureを調べる。
- step1はSubごとに、確認→変更前記録の保存→設定を行う。旧設定は削除しない。
- 診断設定の調査と複製は最大5件ずつ並列に行う。CSVと記録の保存、保存先・DCRの準備、削除・切り戻しは順番に行う。
- None・空欄では新しい送信設定を作らず、step3で旧送信を終了する。RGとLog Analyticsは全行で準備し、StorageはCSVに名前がある場合に準備する。
- step3はstep2を実行し、全件成功後に旧関連→旧診断設定の順に削除する。
- rollbackは旧設定の復元を先に済ませ、新設定を元の状態へ戻す。保存先と保存済みログ、新規DCR本体は残す。

設定値、CSVの詳細、実行コマンド、これまでのWindows検証・実Azureでの実測は[正本の説明資料](../procedural-migration/README.md)を参照してください。

## コメント以外が同じであることの確認

PowerShell Parserで、各ファイルの構文、コメントを除いたトークン列、構文木の構造を正本と比較します。`#Requires`は実行条件なので比較対象に残します。正本6本のハッシュも作業前後で照合します。6本とも、実行トークン・構文木・コード行が一致し、構文エラーは0件です。正本のコメントを残したうえで、説明コメントを469行追加しています。

学習版そのものに既存の回帰試験を適用し、LinuxのPowerShell 7.5.4で72ケース・992判定が成功しました。CLI／HTTP応答を再生する試験で、実際の並列処理と工程コードを使い、Azureへの操作は行っていません。
