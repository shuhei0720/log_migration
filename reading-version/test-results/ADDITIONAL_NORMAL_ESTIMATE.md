# 追加正常テストの構成と、承認時の見積もり

この資料は、過去の追加正常テストで使った構成案と計画見積です。元のスクリプトで環境を作り、移行4工程を完了した記録を説明し直しています。後に中止した再試験の追加予算とは別です。実測時間と削除結果は[検証結果](REPORT.md)を参照してください。

採用したのは、**選んだ50タイプを作り直す案・総額10,000円（従来6,000円に4,000円追加）**です。代表的なリソースだけを作る案は採用していません。前回の試験で作ったリソースを削除した後、BのNetwork・Computeの2件だけは解除待ちを持ち越し、了承を得て再登録しました。元は未登録だったことの証明と、解除待ちの記録は残しています。

|項目|採用：選んだ50タイプを作り直す案|未採用：代表的なリソースだけを作る案|
|---|---|---|
|作成するリソース|依頼の新規50タイプ、補助を含め53タイプ・親リソース65件。負荷NSG300個は再作成しない|親リソース15件：VM2・VMSS2・旧DCR2・移行しないDCR・Log Analytics・ストレージ・NIC・NSG|
|配置先|2サブスクリプション・4地域|2サブスクリプション・3地域。50タイプ・4地域をすべて作り直す確認は含まない|
|確認する内容|各タイプと既知の子リソースで、環境作成から移行・削除まで確認|代表的なリソースで共通の移行処理を確認。50タイプを作り直す確認には含めない|
|作成から削除完了まで|待機・移行を含め2～3時間を計画|同じく2～3時間を計画|
|追加正常テストの見積|**約3,090～3,693円**|**約1,273～1,351円**|
|前の試験6,000円枠との合計見積|約9,090～9,693円|約7,273～7,351円|
|全体の計画予算|**10,000円（承認済み）**|8,000円（未採用）|

見積もりには、サービスの利用登録、検証用VNetと固定サブネット、検証用Windows、結果を回収する保存先の準備を含めました。配布する環境作成コード自体は、既存VNetのリソースIDを参照します。2～3時間とWindows準備0.5時間は計画値で、実測値ではありません。

未確定費用と少量データの予備1,000円、10%の税予備を含みます。採用した案では、NATログの月額料金、SQL・ACRの日額料金など、短時間でも発生する最低料金も確保しました。

実行した順序は、環境作成→旧設定の準備→事前確認→複製→照合→旧設定削除→保存先・新設定の確認→全削除・元状態の確認です。ログが実際に届くのを待つ試験は行っていません。実行版を固定し、移行4工程を各1回実行して成功しました。App Serviceは作成条件に合わせ、移行前にLinux S1からP0v3へ変更しています。環境作成時の失敗と構成変更は、移行4工程の成功と分けて記録しました。

採用した案では、Code Signing・Bing・ExpressRoute・Databricks・旧Redisは省略しました。理由は、契約・退役・既存ネットワークの条件などです。代表的なリソースへ縮小した試験を、選んだ50タイプで成功した結果として扱ってはいません。

当初参照した2026年11月25日00:23 UTCの税前2,151.05円は、その取得時点の反映額です。実コストの取得履歴・小数値・条件は、元の[evidence.json](../../test-results/evidence.json)の`actualCost`にあり、同ファイルに保存した最新値は`latest`です。概要は[検証結果](REPORT.md)にあります。請求データの反映完了は確認できず、最終実費と残予算は未確定です。11月19日分2,287.39円は、この計画から分けています。表の金額はRetail単価と予備で作った見積もりで、実際の請求額ではありません。
