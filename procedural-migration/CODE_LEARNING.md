# 正本を上から読むための学習ガイド

この資料を横に置き、各節のリンク先のコードを上から読んでください。Subはサブスクリプション、RGはリソースグループ、DCRはデータ収集ルールです。実行コマンドとCSVの詳しい指定は[README](README.md)にあります。

全体の流れは「事前確認（任意）→複製→確認→旧設定の削除」です。切り戻しは、この流れとは別に必要なときに実行します。

## 最初に覚える書き方

|コード|読み方|
|---|---|
|`$target.SubscriptionId`|`$target`の中のSub IDを取り出す|
|`@{ Id = '...' ; Kind = 'Storage' }`|名前と値を組にした辞書。設定をひとまとめにする|
|`@(...)` / `+=`|一覧として扱う／一覧の末尾へ追加する|
|`foreach ($target in $targets)`|対象一覧から1件ずつ取り出す|
|`if ($matched) { continue }`|一致していれば、その件の残りを飛ばして次へ進む|
|`一覧 \| Where-Object { $_.Kind -eq 'Diagnostic' }`|診断設定だけを選ぶ。`$_`は処理中の1件|
|`try { ... } catch { ... }` / `throw`|失敗を捕まえて対応する／エラーとして続行を止める|
|`$null` / `$null = 処理`|値がない／処理の戻り値を使わない|

`-eq`は「等しい」、`-ne`は「等しくない」です。関数名の後ろの`-Target $target`は、「Targetという引数に、この値を渡す」と読みます。

## 1. common.ps1：設定と、繰り返し使う処理

[common.ps1](common.ps1)を開きます。入口の各スクリプトにある`. (Join-Path ... 'common.ps1')`は、このファイルの変数と関数を読み込む処理です。

**先頭の設定値。** 移行元ワークスペース、環境、新診断設定名などを指定します。続く`$environmentSettings`には環境別の旧DCRとポリシー割り当てがあり、指定環境のリソースIDを組み立てます。`$migrationContext`は、別環境の記録を取り違えないための照合情報です。

**続く4つの関数。** `function`は処理の定義です。中身は、その関数が呼ばれたときに動きます。

|関数|入力から何を返すか|
|---|---|
|`Invoke-ArmRequest`|リソースID・操作・設定本文を受け、Azureの応答を返す。GETは取得、PUT/PATCHは設定、DELETEは削除|
|`Test-Configuration`|現在値と期待値を受け、一致するかを`true`/`false`で返す。`-Exact`は余分な項目も確認|
|`Get-WritableBody`|取得した応答から、保存・書き戻しに使う設定本文を返す。読み取り専用の項目は除く|
|`Read-MigrationRecord`|対象Subの変更前記録を返す。初回は`null`。環境やCSVが記録と違えば停止|

**CSVの読込み。** `Import-Csv`から1行ずつ取り出し、必須値・送信先フラグ・Storage名を確認します。Sub名またはIDを一意に特定し、`$targets`へ追加します。`-SkipCsv`が付いた呼出しでは、この読込みを省きます。

**最後の`Get-MigrationPlan`。** 現在のAzureを調べて、旧設定と作成予定先を返す5つ目の関数です。中も上から次の順です。

1. リソース一覧を取得し、通常一覧にないStorageの子サービスを加える。
2. 移行元ワークスペース宛ての旧診断設定を探す。ここは最大5件ずつ並列。
3. 指定した旧2DCRから、このSubに属する関連付けを集める。
4. 適用ポリシー、地域略称、Storage名とZRS対応、新設定名と追加枠を確認する。
5. 結果を`$plan`に入れて返す。ここでは設定を作成・削除しない。

`-OnlyOldSettings`付きなら、旧設定の調査までで戻ります。後の確認工程がこの使い方をします。

## 2. precheck.ps1：確認だけを行う

[precheck.ps1](precheck.ps1)は短い入口です。commonを読み、`foreach`で各Subの`Get-MigrationPlan`を呼びます。成功・失敗を`precheck_results.csv`へ出し、失敗があれば最後にエラーで終わります。

Azureの変更や変更前記録の保存は行いません。次のstep1は、この結果を入力にせず、その時点で改めて調査します。

## 3. step1_copy.ps1：調査・記録・設定

[step1_copy.ps1](step1_copy.ps1)では、外側の`foreach ($target in $targets)`が「1つのSubを調査して設定し、次のSubへ進む」という区切りです。内側をブロックコメントに沿って読みます。

**① 調査する。** `Read-MigrationRecord`で既存記録を読み、`Get-MigrationPlan`で現在の旧設定・作成予定先を調べます。初回なら記録はありません。

**② 設定値を組み立てる。** `$plan`に、Waiver、保存先RG・Log Analytics、地域別Storageと1,095日のライフサイクルを追加します。旧DCR関連があればEvent/Syslogの総保持も1,095日にします。続いて新DCR・関連付け、旧ログ・メトリックを引き継ぐ新診断設定を組み立てます。この段階はまだAzureへの書込み前です。

送信先が`None`・空欄の側は、新しい送信設定を組み立てません。保存先は準備し、旧設定はstep3の削除対象に残ります。StorageはCSVに名前がある場合に準備します。

**③ 変更前の値を取得する。** 変更するWaiver・DCR・関連付けについて`Before`を記録します。再実行では最初の`Before`を使います。新規DCRの`KeepOnRollback`は、切り戻しでも本体を残す指定です。

**④ 記録を保存する。** 初回は計画を記録にし、再実行は新しく見つかった対象を追記します。保存済みの旧設定が消えた・変わった場合は停止します。記録は一時ファイルへ書いてから置き換え、Azureを書き換える前に保存します。

ここで3つの一覧を押さえると、後半が読みやすくなります。

|一覧|中身|
|---|---|
|`OldSettings`|旧診断設定・旧DCR関連。`Body`が復元する旧設定値|
|`NewSettings`|新送信設定とWaiver。`Body`が今回の設定値、`Before`が変更前の値|
|`Destinations`|保存先RG・Storage・Log Analyticsなど。切り戻しでも残す|

各項目の`Id`は操作先、`Kind`はこのコード内の分類です。`Before = null`は「元はなかった」を表します。記録にはログデータを保存しません。

**⑤ 順番に設定する。** Waiver→保存先→DCR・関連付けの順です。毎回現在値を取得し、一致していれば`continue`で書込みを省きます。必要な場合だけ設定し、取得し直して一致を確認します。既存保存先では、変更対象外の通信規則や別名のルールなどを残します。

**⑥ 診断設定を複製する。** 準備が済んだSubで、最大5件ずつ並列に処理します。`$using:...`は並列処理の中から外側の値を参照する書き方です。各件の結果を集め、失敗だけを`copy_failures.csv`へ出します。ここで旧設定は削除しません。

## 4. step2_verify.ps1：記録と現在値を比べる

[step2_verify.ps1](step2_verify.ps1)もSubごとに処理します。

1. step1の記録を読む。記録がなければ失敗。
2. 旧設定を再調査し、記録後に追加・変更された対象がないか確認する。既に削除された旧設定は許可する。
3. `Destinations`と`NewSettings`の全項目を取得し、記録の設定値と比較する。
4. `verify_results.csv`へ結果を出す。1件でもNGならエラーにする。

先頭の`param([switch]$PassThru)`は、呼出し方を切り替える引数です。付けると確認済みの記録を返し、次のstep3がそれを使います。

## 5. step3_delete.ps1：全件確認後に旧設定を外す

[step3_delete.ps1](step3_delete.ps1)の先頭の`& ... step2_verify.ps1 -PassThru`で、確認工程を実行します。全件成功してから、旧DCR関連→旧診断設定の順で削除します。

各件でも、削除直前の旧設定が記録と同じか確認します。送信を続ける指定なら、対応する新設定も再確認します。既に消えている旧設定はスキップします。失敗した時点で停止し、`delete_failures.csv`へ対象と理由を出します。

`None`・空欄の側も旧設定を削除するため、その側の送信はここで終了します。

## 6. rollback.ps1：旧設定を戻してから新側を戻す

[rollback.ps1](rollback.ps1)では、先頭の`SubscriptionIds`で対象を絞れます。指定しなければ記録の全Subが対象です。CSVは読まず、保存済み記録を使います。

最初のループは照合だけです。現在値が保存した値と違う場合、外部で変更された設定を上書きしないよう停止します。

次の`foreach ($phase in @('Old', 'New'))`が復元の順番です。

1. **Old：** 旧DCR関連→旧診断設定を、記録した`Body`へ全件復元する。
2. **New：** 新側を`Before`へ戻す。`Before = null`なら今回作った設定を削除する。

書込みごとに取得し直して確認します。新規DCR本体、保存先と保存済みログは残します。元からあったWaiverも残し、今回新設したWaiverだけを解除します。失敗は`rollback_failures.csv`へ出します。
